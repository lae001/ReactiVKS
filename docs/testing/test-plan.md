# План тестирования

Результат задачи EMO-54 (спринт 3; в `docs/plan/sprint-3.md` эта задача значится как EMO-59). Ответственный – тестировщик
(Зимирев К. М.), сценарии согласует аналитик. План развивает архитектурный уровень
([07-development.md, 7.7](../architecture/07-development.md)) и опирается на журнал дефектов
([defect-log.md](defect-log.md)); подробные методики испытаний появятся в «Программе и методике испытаний» (EMO-97).

## 1. Цели и объем

Подтвердить, что Система выполняет прецеденты UC-1…UC-7 и нефункциональные требования концепции (раздел 8.6;
таблица в [01-overview.md](../architecture/01-overview.md)), и что MVP (04.12.2026) не содержит блокирующих и
критических дефектов.

| В объеме | Вне объема первой версии |
|---|---|
| Все сервисы и клиент из [02-containers.md](../architecture/02-containers.md), модель распознавания (качество), видеосвязь через LiveKit | Запись встреч, анализ голоса, мобильные клиенты, зал ожидания (см. 1.6 обзора архитектуры); тестирование самого LiveKit и браузерных реализаций WebRTC |

## 2. Виды тестов

| Вид | Что проверяется | Инструменты | Где запускается | Когда |
|---|---|---|---|---|
| Модульные (frontend) | Чистые функции, формы, защитники маршрутов, страницы с подменой API | Vitest, Testing Library, jsdom | CI, локально (`pnpm test`) | Каждый PR |
| Модульные (backend, ML) | domain/services, агрегация, сглаживание, конвейер кадров | pytest, pytest-asyncio | CI | Каждый PR |
| Интеграционные | Репозитории + PostgreSQL, Kafka (outbox, смещения, DLQ), вебхуки LiveKit (фикстуры) | pytest, testcontainers | CI | Каждый PR сервиса |
| Контрактные | Схемы событий `vks_contracts`; OpenAPI ↔ типы клиента | pydantic JSON Schema, openapi-typescript | CI | Каждый PR, затрагивающий `docs/api` |
| Сквозные (e2e) | UC-2…UC-5 в двух браузерах, фейковое видео с записанными эмоциями | Playwright | Локально и на стенде | Конец каждого спринта, с итерации 2 |
| Функциональные (ручные) | UC-1…UC-7 по сценариям, макетам и ТЗ | Сценарии (EMO-41), GitHub Issues | Стенд | Спринты 4–6 |
| Кросс-браузерные | Вход, лобби, комната, панель эмоций в поддерживаемых браузерах (раздел 4) | Ручной прогон + Playwright (Chromium, Firefox) | Локально, стенд | Спринт 6 |
| Нагрузочные | 5 встреч × 10 участников: CPU/RAM, задержка медиа, частота анализа, задержка панели | `lk load-test`, ML-агент, Prometheus | Демонстрационный сервер | Спринт 6 (EMO-103) |
| Сетевые | Соединение через TURN, ограничение канала | `chrome://webrtc-internals`, `tc netem` | Стенд, две сети | Начало спринта 5, спринт 6 |
| Качество модели | accuracy, macro-F1, матрица ошибок | `ml/training` (`evaluate`) | ML-окружение | После каждой версии модели |
| Доступность и приватность | Цвет не единственный носитель смысла, контраст, фокус с клавиатуры; согласие и отсутствие кадров в хранилище | Axe/проверка контраста ([emotion-visualization.md](../frontend/emotion-visualization.md)), ручная проверка | Локально, стенд | Спринты 4–6 |
| Приемочные | Критерии раздела 7 на демонстрационном стенде | Ручной прогон по ПМИ | Стенд | Спринт 7 (EMO-121) |

Автоматические проверки frontend в CI: `lint → format:check → typecheck → test → build`. Playwright в CI пока не
включен: e2e требуют запущенных бэкенда и LiveKit, поэтому до развертывания стенда запускаются вручную
(`pnpm test:e2e`).

## 3. Окружения

| Окружение | Состав | Назначение |
|---|---|---|
| Локальное (разработчик) | `pnpm dev`; сервисы по мере готовности; LiveKit в dev-режиме (`--dev`, ключи `devkey`/`secret`); фейковая камера Chrome | Модульные, интеграционные, отладка e2e |
| CI (GitHub Actions) | Образы runner, testcontainers; без камеры и LiveKit | Модульные, интеграционные, контрактные |
| Стенд | Docker Compose на демонстрационном сервере (8 vCPU, 16 ГБ, без GPU), TLS, LiveKit с внешним IP и TURN | e2e, нагрузочные, сетевые, кросс-браузерные, приемка |

Ограничения слабых машин: e2e и ручные прогоны запускаются по одному браузеру, `workers: 1` в Playwright; нагрузочные
тесты на ноутбуках разработчиков не запускаются.

Тестовые данные: пользователи создаются фикстурами и удаляются после прогона; видео – заранее записанные ролики
участников команды с метками эмоций (фейковая камера `--use-file-for-fake-video-capture`). Записи и кадры людей,
не давших согласия, не используются (152-ФЗ).

## 4. Браузеры

Совпадает с [docs/frontend/README.md](../frontend/README.md) («Поддержка браузеров»).

| Браузер | Версии | Роль | Автоматически | Вручную |
|---|---|---|---|---|
| Chrome | последние 2 | организатор, участник; основной для e2e | Playwright (Chromium) | да |
| Edge | последние 2 | организатор, участник | – (тот же движок) | выборочно |
| Яндекс Браузер | последние 2 | организатор, участник | – | да |
| Firefox | последние 2 | организатор, участник | Playwright (Firefox) | да |
| Safari | 17+ | только участник | – | да, macOS |

Вручную проверяются: проверка устройств в лобби, переключение камеры и микрофона во время встречи, повторное
подключение, отображение панели эмоций. Размеры экрана: 1280 и 360 px (как в макетах); мобильные браузеры – только
как участник и без гарантий первой версии.

## 5. Покрытие требований

| Прецедент | Модульные | Интеграционные | e2e | Ручные |
|---|---|---|---|---|
| UC-1 Регистрация, вход | + | + | + | + |
| UC-2 Создание встречи | + | + | + | + |
| UC-3 Присоединение по ссылке | + | + | + | + |
| UC-4 Встреча и панель эмоций, отзыв согласия, отказ ML | + | + | + | + |
| UC-5 Просмотр отчета | + | + | + | + |
| UC-6 Экспорт | + | + | – | + |
| UC-7 Администрирование | + | + | – | + |

| Нефункциональное требование | Значение | Способ проверки |
|---|---|---|
| Задержка аудио/видео | ≤ 400 мс | Нагрузочный и сетевой тест, `webrtc-internals` |
| Встреч / участников | ≥ 5 / ≥ 10 | `lk load-test` 5 × 10 |
| Задержка результатов анализа | ≤ 2 с | Измерение на клиенте (`ts` отсчета – время отрисовки, `server_time` из `welcome`) |
| Частота анализа | ≥ 2 кадра/с на участника | Метрики ML-агента при 10 участниках |
| Точность модели | accuracy ≥ 65 % (7 классов) | `evaluate` на тестовой выборке и записях команды |
| Подключение по ссылке | ≤ 5 с | e2e с замером от «Войти» до первого видеокадра |
| Сбой ML не прерывает встречу | – | Остановка ML-сервиса во время e2e (UC-4, альтернатива 5а) |
| Покрытие серверного кода | ≥ 60 % | coverage в CI |
| Приватность | Кадры не сохраняются | Проверка хранилищ после встречи; анализ не идет без согласия |
| Развертывание одной командой | – | `docker compose up` на чистом сервере |

## 7. Критерии

**Начала приемочного прогона:** сборка проходит CI; стенд развернут; нет открытых блокирующих дефектов предыдущего прогона.

**Приемки MVP (04.12.2026):**

- все сценарии UC-1…UC-5 пройдены в Chrome и Firefox без блокирующих и критических дефектов;
- открытых `severity:blocker` и `severity:critical` нет; для `severity:major` есть обходной путь и план исправления;
- задержка панели эмоций ≤ 2 с (медиана на 5 участниках), частота анализа ≥ 2 кадра/с;
- анализ не запускается без согласия, отзыв согласия останавливает его; кадры не попадают в хранилища;
- сбой ML-сервиса не прерывает встречу, организатору показан статус анализа.

**Приемки Системы (25.12.2026):** дополнительно – UC-6 и UC-7, нагрузка 5 × 10 в пределах НФТ, покрытие серверного
кода ≥ 60 %, accuracy модели ≥ 65 % или зафиксированный план улучшения, поддерживаемые браузеры пройдены вручную.

**Остановки тестирования:** недоступен стенд или LiveKit, блокирующий дефект в основном сценарии. Возобновление – после
исправления и дымового прогона (вход → создание → присоединение двух участников → видео).

## 8. Риски

| Риск | Мера |
|---|---|
| Слабые машины не тянут два браузера и сервисы одновременно | Один браузер за раз, тяжелые прогоны на стенде |
| Соединение через NAT из разных сетей | Проверка TURN в начале спринта 5, тест из двух сетей |
| Нестабильность фейкового видео и распознавания на нем | Записанные ролики с известными эмоциями, допуск по классам, а не по значениям |
| Нехватка времени тестировщика (11 ч второстепенных задач в спринте) | Приоритет UC-2…UC-4, автоматизация только критического пути |
| Недоступность GitHub (риск 8 устава) | Журнал дефектов дублируется в `defect-log.xlsx` |
