## Реальный стенд

Исходные процессы пользователя сохранены. Vite 5183 направляет встречи в прежний
meeting-service 8012, auth в 8001. Старый Vite 5173 направляет встречи в dev-api 8002.

Для новой интеграции использованы отдельные процессы meeting-service 8013,
realtime 8080, analytics 8003 и временный Vite 5184. Auth 8001 и LiveKit 7890/7891
переиспользованы. Вебхук LiveKit по существующей конфигурации доставляется в
старый процесс 8012, использующий общую БД. После подключения новый API 8013
показывает online=2. Это сочетание процессов явно входит в условия прогона.

Перед запуском применены штатные миграции команды — meeting 0003 → 0004
(добавлена очередь синхронизации согласия), analytics → 0002. Их исходный код
сохранён без правок. Конфигурации с секретами находятся только в `/tmp/reactivks-sprint6`,
файлы env имеют права 0600. Аналитика использовала настройки локального стенда
из предоставленного командой `.env.example`.

## Что открыть для показа

На существующем http://localhost:5183 войти тестовым организатором.

1. Открыть «Встречи», ввести часть названия, выбрать даты и статусы разделов.
   «Сбросить фильтры» возвращает полную выдачу. «Ещё» использует курсор своего раздела.
2. В «Прошедших» открыть «Отчет» или название завершённой встречи. CSV доступен
   по завершении встречи, PDF — после готовности отчёта. При текущем отсутствии
   серверного экспорта показана ошибка сервиса. Контрактный сценарий ниже показывает
   готовый отчёт и скачивание тестовых файлов.
3. Открыть `/settings`, изменить анализ и частоту, сохранить, обновить страницу,
   перейти в `/meetings/new`. Новая форма использует сохранённые значения.
4. Организатору `/admin` показывает «Нет доступа». Существующий администратор
   получает список пользователей, подтверждение блокировки/разблокировки и
   фактическую недоступность ещё не реализованных разделов встреч и состояния.
   Контрактный тест использует тестовую роль admin без создания учётной записи.

```sh
cd /Users/z.kirill/dev/ReactiVKS/frontend
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"
pnpm exec playwright test -c playwright.sprint6.config.ts --project=chromium
```

Команда поднимает свой Vite 5184 либо переиспользует его. Все API в этом файле
контрактные, данные эмоций тестовые. Артефакты находятся в `/tmp/reactivks-sprint6/playwright`.
Для визуального наблюдения добавить `--headed`.
