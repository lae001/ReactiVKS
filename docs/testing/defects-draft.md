## Черновик-1. Комната: стили LiveKit перебивают высоту окна, панель управления «плывет» при двух видео

| Поле | Значение |
|---|---|
| ID | Не присвоен (`BUG-` + номер issue после создания) |
| Заголовок | Комната: стили LiveKit перебивают высоту окна, панель управления «плывет» при двух видео |
| Компонент | `frontend` |
| Прецедент / требование | UC-4 (комната); ИНТ-2.2 ([tz-interface-requirements.md](../frontend/tz-interface-requirements.md)), макет комнаты ([mockups.md](../frontend/mockups.md)) |
| Шаги воспроизведения | 1. Запустить `livekit-server --dev --bind 127.0.0.1`, `pnpm dev:api` и клиент с `VITE_API_MODE=http`.<br>2. Организатор создает встречу и нажимает «Начать встречу»; гость входит по ссылке из лобби.<br>3. В Chromium 1280×720 открыть комнату организатора, когда в ней двое участников с видео.<br>4. Автотест: нажать кнопку «Чат» или «Завершить встречу» на панели управления организатора (`pnpm test:e2e:room`). |
| Ожидаемый результат | Комната занимает всю высоту окна (`h-dvh`), галерея делит оставшееся место между шапкой и панелью управления; панель внизу и неподвижна, ее кнопки доступны (макет комнаты, [mockups.md](../frontend/mockups.md)) |
| Фактический результат | Корневой элемент `.lk-room-container` не получал высоту окна: стили LiveKit (без слоя) перебивали класс `h-dvh` Tailwind (в промежуточной проверке вычисленная высота корня была 121 px вместо 720), поэтому высота комнаты определялась содержимым. С двумя видео галерея «раскачивалась» (высота областей 497 ↔ 1912 px, сетка 481 ↔ 1896 px), панель управления перескакивала между y = 553 и y = 1968 за пределы окна. Playwright: `element is not stable`, клик не выполнялся |
| Окружение | Chromium headless shell (Playwright, `chromium_headless_shell-1248`), macOS (Darwin 25.6, arm64), `livekit-server` 1.13.9 `--dev`, `dev-api`, сборка `71ac284` (ветка `feat/room-livekit`, этап А), окно 1280×720, фейковая камера Chromium |
| Вложения | Измерения размеров из диагностического прогона и трассировка Playwright – только локально (в репозиторий не добавлены); скриншот комнаты после исправления – [mockups/room-live-1280.png](../frontend/mockups/room-live-1280.png) |
| Серьезность | `severity:major` (предложение): основное действие (кнопки управления) недоступно при двух видео; обходной путь – прокрутка страницы |
| Приоритет | Назначает руководитель проекта |
| Исполнитель | Назначает руководитель проекта (исправил разработчик клиента) |
| Статус | **Исправлен** в `688759d` (ветка `feat/room-livekit`): высота комнаты задается инлайн-стилем `style`, галерея внутри абсолютно позиционирована. Найден автотестом до слияния. Повторный ручной прогон на других браузерах не выполнялся |
| Причина | Стили `@livekit/components-styles` не лежат в слое CSS и по специфичности побеждают утилиты Tailwind |
| Тест, фиксирующий исправление | `e2e/room.room.ts` (клики по панели управления при двух видео); модульного теста нет – проблема видна только в браузере |

## Черновик-2. Комната: после «Завершить встречу» организатор не переходит в карточку встречи

| Поле | Значение |
|---|---|
| ID | Не присвоен (`BUG-` + номер issue после создания) |
| Заголовок | Комната: после «Завершить встречу» организатор не переходит в карточку встречи |
| Компонент | `frontend` |
| Прецедент / требование | UC-4 (завершение), [03-scenarios.md](../architecture/03-scenarios.md), 3.8; [site-structure.md](../frontend/site-structure.md), 4.3 («Завершить встречу» ведет в карточку встречи) |
| Шаги воспроизведения | 1. Окружение как в Черновик-1; организатор и гость в комнате.<br>2. Организатор нажимает «Завершить встречу» и подтверждает в диалоге «Завершить встречу для всех?».<br>3. Автотест ожидает адрес `/meetings/<id>` (`pnpm test:e2e:room`, шаг «завершение встречи»). |
| Ожидаемый результат | Запрос `POST /meetings/{id}/end` выполнен, организатор открывает карточку встречи со статусом «Завершена» |
| Фактический результат | Встреча завершалась на сервере, но адрес страницы не менялся на `/meetings/<id>`: `expect(page).toHaveURL` не выполнился. Экран, на котором оставался организатор, при прогоне не снимался |
| Окружение | То же, что в Черновик-1; сборка `688759d` до исправления (код этапа Б в рабочем дереве) |
| Вложения | Вывод Playwright (локально, не в репозитории) |
| Серьезность | `severity:minor` (предложение): встреча завершена корректно; организатор попадает на экран «Встреча завершена» со ссылкой «К карточке встречи», то есть обходной путь есть (по коду экрана; в браузере этот экран не снимался) |
| Приоритет | Назначает руководитель проекта |
| Исполнитель | Назначает руководитель проекта (исправил разработчик клиента) |
| Статус | **Исправлен** в `688759d` (ветка `feat/room-livekit`), найден автотестом до слияния |
| Причина | LiveKit закрывает комнату (`ROOM_DELETED`) раньше, чем клиент обрабатывает ответ REST: компонент комнаты уже заменен экраном выхода и размонтирован, а обработчик `onSuccess`, переданный в `mutate()`, после размонтирования не вызывается. Причина установлена разбором кода и подтверждена тем, что перенос обработчика на уровень `useMutation` устранил сбой в автотесте |
| Тест, фиксирующий исправление | `e2e/room.room.ts` (шаг завершения встречи); модульный тест `RoomShell.test.tsx` переход после подтверждения проверяет без реального закрытия комнаты |

## Что не вошло

В журнал не включены наблюдения, которые не являются дефектами продукта: сбои самих тестов при разработке (неверные
селекторы, неоднозначные имена элементов), решения по контракту, поднятые вопросами к бэкенду, и найденное в
`dev-api` (временный сервер, не часть продукта). Открытые вопросы к бэкенду ведутся отдельно в отчетах по веткам.
