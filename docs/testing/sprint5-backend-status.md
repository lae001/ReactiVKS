# Спринт 5. Демонстрация бэкенда (EMO-88)

На локальном стенде 12.11.2026 запущены auth-service, meeting-service, realtime-service, analytics-service,
PostgreSQL, Kafka, Redis и LiveKit. Гость подключался к комнате через RTC-клиент. Тестовый издатель подавал
события ML в Kafka. Готовый отчет и `report.ready` создал analytics-service.

| Проверка | Результат |
|---|---|
| Организатор подписывается на `/ws` с подпротоколом `vks.v1` | Получен снимок встречи. Чужой токен получает `4403` |
| Событие `emotion.sample` из Kafka | Сообщение `emotion.update` получено через 251 мс |
| Гость отзывает согласие во время встречи | Получен `participant.status: no_consent`. В REST-ряду остался отсчет до отзыва |
| Издатель прекращает отправку heartbeat | Получен `analysis.status: unavailable`. Подключение гостя к LiveKit сохранилось |
| Организатор завершает встречу | `meeting.ended`, отчет `pending` → `ready`, затем `report.ready` через 5,57 с от запроса завершения |
| Посторонний пользователь запрашивает отчет | `404` |
| Повторное чтение смещения Kafka и расчет ключевых моментов | Интеграционные тесты подтвердили отсутствие дублей, ожидание границы записи и сохранение отметок |

Полный набор тестов бэкенда на отдельной БД PostgreSQL и брокере Kafka прошел: 480 тестов.

Для показа открыть встречу с анализом, подключить гостя с согласием и подписаться на нее от имени организатора.
Подать `ml.status` и `emotion.sample` по [контракту Kafka](../api/events.md) с ключом встречи и UUID гостя.
Отозвать согласие, прекратить heartbeat, завершить встречу и открыть
`GET /api/v1/reports/{meeting_id}` и `GET /api/v1/reports/{meeting_id}/series?resolution=1s`.
Порядок запуска стенда описан в [deploy/README.md](../../deploy/README.md).

Для приемки ML нужны рабочий агент и замер на 10 участниках. Локальный прогон измерял доставку тестового отсчета
и сборку отчета. Частота инференса и время его остановки после отзыва остаются непроверенными.
