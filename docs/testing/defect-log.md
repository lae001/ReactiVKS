# Журнал дефектов (EMO-21)

## Порядок ведения

1. Дефект фиксируется как GitHub Issue с меткой `bug` (либо строка ниже до появления доски).
2. Обязательные поля: заголовок, шаги воспроизведения, ожидаемый и фактический результат, окружение (ОС, браузер, версия), серьёзность, вложения (скриншот, лог консоли).
3. Серьёзность: **Критическая** — система/встреча недоступна; **Высокая** — ключевой сценарий сломан, обхода нет; **Средняя** — есть обход; **Низкая** — косметика.
4. Статусы: Новый → Подтверждён → В работе → Исправлен → Проверен (закрыт) / Отклонён.
5. Исправление — отдельным PR со ссылкой на дефект; закрывает дефект тот, кто его нашёл, после повторной проверки.
