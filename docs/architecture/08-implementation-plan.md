## 8.2 Порядок сборки вертикального среза

1. Инфраструктура и общий код: compose (PostgreSQL, Redis, Kafka, LiveKit) → `vks_common` → `vks_contracts`.
2. Плоскость управления: auth-service → meeting-service → frontend (вход, встречи, лобби, комната).
3. Плоскость анализа: ML-конвейер → агент LiveKit → Kafka → realtime-service → панель эмоций.
4. Сохранение и отчеты: analytics-service → отчет → экспорт.
5. Эксплуатация: администрирование, фоновые задачи, мониторинг, развертывание.

## 8.3 Приоритеты при нехватке времени

Если сроки под угрозой (риски 1, 2, 14 устава), архитектура допускает упрощения без переделки контрактов:

1. PDF-экспорт → только CSV + печать страницы отчета браузером.
2. analytics-service и realtime-service временно в одном процессе (разные модули, те же контракты и топики Kafka).
3. Модель v1 – предобученная открытая модель с дообучением только последнего слоя.
4. Админ-раздел → только CLI-команды и `docker compose ps/logs`.

Не упрощаются: механизм согласия, запрет хранения кадров, изоляция ML от медиаплоскости.
