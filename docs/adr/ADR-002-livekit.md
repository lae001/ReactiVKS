# ADR-002. LiveKit в качестве медиасервера и сигнализации WebRTC

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Нужен готовый открытый SFU (устав: медиасервер не разрабатывается с нуля) для 10 участников × 5 встреч, с обходом NAT,
клиентским SDK для React и возможностью серверному компоненту на Python получать декодированные видеокадры.
Риск 14 устава – сложность видеосвязи и нехватка времени на ML.

## Решение
LiveKit Server (Apache 2.0) со встроенным TURN. Сигнализация WebRTC выполняется LiveKit (а не собственным WebSocket
Backend, как предполагалось в концепции). Backend управляет LiveKit через Server API и выдает токены доступа.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **LiveKit** | Готовые SDK (JS, React-компоненты, Python), встроенный TURN, simulcast/dynacast, токены, вебхуки, фреймворк агентов для ML | Зависимость от экосистемы LiveKit |
| mediasoup | Гибкость, популярность | Сигнализацию, клиентскую логику, TURN (coturn) и получение кадров для ML нужно писать самим; сервер на Node.js |
| Jitsi Videobridge | Полноценный стек | Сложно встраивать собственный UI и извлекать дорожки для ML, тяжелое развертывание |

## Последствия
- Отклонение от концепции: сигнализация – через LiveKit; собственный WebSocket используется только для панели эмоций.
- Отдельный coturn не нужен (встроенный TURN); при проблемах – coturn подключается конфигурацией.
- Чат реализуется средствами LiveKit ([ADR-008](ADR-008-chat-via-livekit-data.md)).
- Зависимость изолирована в `LiveKitGateway` и транспорте ML-сервиса ([livekit-integration.md](../api/livekit-integration.md)).
