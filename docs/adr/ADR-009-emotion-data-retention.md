# ADR-009. Хранение только посекундных агрегатов, без кадров

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Концепция: видеокадры не сохраняются, хранятся только агрегированные результаты; 152-ФЗ. Отчету нужны графики
динамики и экспорт исходных временных рядов в CSV.

## Решение
- Кадры – только в памяти ML-сервиса в пределах одного такта.
- Отсчеты с частотой кадров – только в топике Kafka `emotion.samples` (эфемерно, хранение 1 ч).
- В БД – посекундные средние вероятности 7 классов и доля кадров с лицом (`emotion_series`).
- CSV-экспорт отдает посекундные ряды («исходные данные» в терминах концепции).

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Хранить каждый отсчет | Максимум детализации | Больше объем без пользы для отчета; «сырые» данные |
| **Посекундные агрегаты** | Достаточно для графиков и CSV, минимизация | Потеря внутрисекундной динамики (не нужна) |
| Только итоговая сводка | Минимум данных | Нельзя построить графики динамики |

## Последствия
- Срок хранения по умолчанию 1 год с автоматической очисткой; удаление встречи удаляет аналитику физически.
- Для оценки качества модели на реальных встречах используются только записи команды, сделанные отдельно с согласия.
