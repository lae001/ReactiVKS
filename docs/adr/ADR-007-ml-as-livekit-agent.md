# ADR-007. ML-модуль как агент LiveKit Agents

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
ML-модуль должен получать видео каждого согласившегося участника с сервера (не из браузера организатора), обрабатывать
2–5 кадров/с, масштабироваться и не влиять на видеосвязь при сбое.

## Решение
emotion-ml-service – воркер фреймворка LiveKit Agents (Python). meeting-service явно диспетчеризует агента в комнату,
LiveKit распределяет задания между воркерами. Агент подписывается только на видеодорожки участников с
`vks.consent = granted`, получает декодированные кадры (`VideoStream`), инференс – ONNX Runtime.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **LiveKit Agents** | Готовые диспетчеризация, балансировка, перезапуск заданий, декодирование кадров | Привязка к LiveKit |
| Собственный участник на `livekit` rtc SDK | Меньше зависимостей | Балансировку и управление заданиями писать самим |
| Анализ в браузере организатора | Нет серверной нагрузки | Нагрузка на клиент, зависит от организатора, нет контроля согласия |
| Анализ в браузере каждого участника (отправка вероятностей) | Минимум трафика и приватность | Нельзя доверять клиенту, слабые устройства, сложно обновлять модель |
| Egress-запись → анализ | – | Не реальное время, противоречит запрету записи |

## Последствия
- Горизонтальное масштабирование – увеличение числа реплик ML-сервиса, вынос на узел с GPU.
- При падении воркера LiveKit повторно назначает задание.
- Препроцессинг вынесен в общий модуль, используемый и в обучении ([ml-model.md](../ml/ml-model.md)).
