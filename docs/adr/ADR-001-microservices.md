# ADR-001. Микросервисная архитектура из пяти сервисов

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Концепция описывает единый Backend, медиасервер и ML-модуль. Команда решила строить Систему как набор микросервисов.
Ограничения: 3 человека, ≈ 310 чел.-ч, один сервер 8 vCPU / 16 ГБ. ML-нагрузка принципиально отличается от
остальной (CPU/GPU, тяжелые зависимости), а ее отказ не должен прерывать встречу.

## Решение
Пять собственных сервисов, выделенных по бизнес-возможностям и характеру нагрузки:

| Сервис | Почему отдельно |
|---|---|
| auth-service | Независимая предметная область, редко меняется, повторно используемая проверка JWT |
| meeting-service | Ядро плоскости управления и единственная точка интеграции с LiveKit |
| realtime-service | Долгоживущие соединения, иной профиль нагрузки, чем у REST |
| analytics-service | Тяжелые запросы и генерация PDF не должны влиять на вход во встречи |
| emotion-ml-service | CPU/GPU-нагрузка, тяжелые зависимости, независимое масштабирование и изоляция отказов |

Чат, уведомления, администрирование и экспорт не выделяются в отдельные сервисы (слишком мелкие для команды из 3 человек).

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Модульный монолит + ML-сервис | Проще разработка и развертывание | Не соответствует выбранному командой стилю |
| 3 сервиса (core, analytics, ml) | Меньше накладных расходов | Смешение аутентификации, встреч и WebSocket |
| **5 сервисов** | Четкие границы, изоляция отказов, параллельная работа | Больше инфраструктурного кода, распределенные данные |
| 8+ сервисов | «Чистые» границы | Непосильно для команды, лишняя сложность |

## Последствия
- Общий код (проверка JWT, журналирование, клиент Kafka, outbox, контракты) выносится в `backend/libs`, чтобы не дублировать.
- Данные других сервисов получаются через события и проекции ([ADR-012](ADR-012-kafka.md)).
- Нужны сквозные идентификаторы запросов и централизованные журналы.
- Запасной план при нехватке времени – объединение realtime и analytics в одном процессе без изменения контрактов.
