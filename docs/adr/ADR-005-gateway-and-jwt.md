# ADR-005. Nginx как единая точка входа, JWT RS256 с проверкой в каждом сервисе

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Клиенту нужна одна точка входа (TLS, один домен, CORS не нужен). Сервисы должны проверять пользователя без
обращения к auth-service на каждый запрос.

## Решение
- Nginx: TLS, маршрутизация по префиксам `/api/v1/...` к сервисам, `/ws`, статика SPA, `limit_req`, SNI-маршрутизация TURN/TLS.
- auth-service подписывает access-токены RS256; остальные сервисы проверяют их локально по JWKS (библиотека `vks_common.auth`).
- Внутренние вызовы – REST `/internal/*` с `X-Service-Token`, недоступные извне.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Nginx + JWT в сервисах** | Просто, уже в стеке, нет лишнего сетевого перехода | Логика проверки в каждом сервисе (решено общей библиотекой) |
| Traefik/Kong с проверкой JWT на шлюзе | Централизация | Еще один компонент и конфигурация |
| gRPC между сервисами | Строгие контракты | Лишняя сложность для 2–3 внутренних вызовов |
| Сессии + общий Redis | Мгновенный отзыв | Состояние, обращение к Redis на каждый запрос |

## Последствия
- Блокировка пользователя вступает в силу для REST в течение ≤ 15 мин (срок access-токена) – допустимо.
- Ротация ключей через `kid` в JWKS.
