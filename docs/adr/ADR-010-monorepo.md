# ADR-010. Монорепозиторий `frontend/`, `backend/`, `ml/`

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Пять сервисов, общий контракт событий, одна команда, один docker-compose; документация хранится в репозитории.

## Решение
Один репозиторий: `frontend/` (SPA), `backend/` (uv workspace: `libs/` и `services/<name>/`), `ml/` (сервис инференса и
обучение), `deploy/`, `docs/`. CI с фильтрами по путям. Структура – [07-development.md](../architecture/07-development.md).

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Монорепозиторий** | Атомарные изменения контрактов, единый CI и ревью, простая навигация | Нужны фильтры по путям в CI |
| Репозиторий на сервис | Независимые релизы | Синхронизация контрактов, 6+ репозиториев на 3 человека |

## Последствия
- `ml/emotion_service` зависит от `backend/libs/vks_contracts` как от path-зависимости.
- Веса моделей не хранятся в git (Releases / Git LFS).
