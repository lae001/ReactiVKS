# ADR-004. Один PostgreSQL, отдельная схема на сервис

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Принцип «своя БД у сервиса» конфликтует с ресурсами демонстрационного сервера (16 ГБ) и с простотой резервного
копирования.

## Решение
Один экземпляр PostgreSQL 16; схемы `auth`, `meeting`, `analytics`; у каждого сервиса свой пользователь БД с правами
только на свою схему; отдельные миграции Alembic. Кросс-схемные запросы и внешние ключи между схемами запрещены.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Одна СУБД, схема на сервис** | Логическая изоляция, один бэкап, мало ресурсов | Общая точка отказа, конкуренция за ресурсы |
| Отдельный PostgreSQL на сервис | Полная изоляция | ×3 памяти и эксплуатации |
| Общая схема | Проще всего | Нарушает границы сервисов |
| TimescaleDB для analytics | Удобно для рядов | При объеме ≈ 54 тыс. строк на встречу не нужно |

## Последствия
- Изоляция обеспечивается правами БД, а не соглашением.
- Вынос схемы в отдельный экземпляр – изменение только `DATABASE_URL`.
- Один `pg_dump` покрывает все данные.
