# ADR-011. Transactional outbox для публикации событий

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Автор:** Халецкий Д. Е.

## Контекст
Сервисы с БД меняют данные и публикуют события в Kafka (`meeting.events`, `user.events`, `report.events`). Запись в
PostgreSQL и отправка в Kafka не атомарны: при сбое между ними событие теряется (analytics не узнает о завершении
встречи и не построит отчет, realtime не узнает об отзыве согласия) или публикуется для откатившейся транзакции.
Транзакции Kafka не помогают: они не охватывают транзакцию PostgreSQL.

## Решение
Каждый сервис с БД пишет событие в таблицу `outbox` своей схемы в той же транзакции, что и изменение данных.
Фоновый `OutboxRelay` (`vks_common.kafka`) отправляет записи в Kafka по порядку (идемпотентный производитель,
`acks=all`), дожидается подтверждения и отмечает `published_at`. Потребители идемпотентны по `event_id`.
ML-сервис (без БД, эфемерные отсчеты) публикует напрямую.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Отправка в Kafka после `COMMIT` | Просто | Потеря событий при сбое процесса между операциями |
| Отправка в Kafka до `COMMIT` | Просто | «Призрачные» события при откате |
| **Transactional outbox** | Гарантия «не менее одного раза», порядок | Таблица и фоновый релей; задержка ≤ 1 с (обычно мгновенно по сигналу в процессе) |
| CDC (Debezium + Kafka Connect) | Без кода релея в сервисах, естественно сочетается с Kafka | Еще два тяжелых компонента (Kafka Connect, логическая репликация PostgreSQL) – избыточно для одного сервера |

## Последствия
- Таблица `outbox` в схемах `auth`, `meeting`, `analytics` ([database.md](../backend/database.md)).
- Релей работает под распределенной блокировкой – один на сервис, порядок событий сохраняется.
- Недоступность Kafka не ломает REST-операции: события копятся в outbox и публикуются после восстановления.
- Метрика `outbox_pending` и оповещение при росте.
- При росте нагрузки релей заменяется на Debezium без изменения потребителей (формат таблицы совместим с
  Outbox Event Router).
- Подробности – [conventions.md](../backend/conventions.md#6-публикация-событий-transactional-outbox).
