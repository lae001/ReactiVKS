# Пользовательские потоки

Потоки трех ролей ([site-structure.md](site-structure.md), раздел 1) по прецедентам UC-1…UC-7 из
[03-scenarios.md](../architecture/03-scenarios.md). Диаграммы показывают путь пользователя по экранам клиента;
обмен с сервисами – в [03-scenarios.md](../architecture/03-scenarios.md), тест-сценарии –
[test-scenarios-uc1-uc3.md](../testing/test-scenarios-uc1-uc3.md).

Состояние реализации на 2026-10-28 (спринт 4): UC-1…UC-4 реализованы в клиенте (режим `mock` и режим `http`
на временном `dev-api`), панель эмоций, сводка и отчет (UC-5) – на тестовых данных, экспорт (UC-6) и
администрирование (UC-7) пока заглушки. Где поток еще не реализован, это отмечено в подписи к диаграмме.

Условные обозначения: прямоугольник – экран, ромб – решение системы или пользователя, скругленный – вход
или выход из потока, пунктир – переход по ошибке.

## 1. Организатор

### 1.1 Вход в Систему (UC-1)

```mermaid
flowchart TD
    start(["Открыл приложение"]) --> auth{"Есть сессия?<br/>POST /auth/refresh"}
    auth -- "да" --> meetings["Главная /meetings"]
    auth -- "нет" --> login["/login"]
    login --> reg{"Аккаунта нет?"}
    reg -- "да" --> register["/register<br/>имя, почта, пароль"]
    register --> regok{"Данные верны?"}
    regok -. "нет" .-> register
    regok -- "да, автоматический вход" --> meetings
    reg -- "нет" --> cred["Почта и пароль"]
    cred --> credok{"Вход удался?"}
    credok -. "неверные данные, блокировка,<br/>слишком много попыток" .-> login
    credok -- "да" --> meetings
    meetings --> out["«Выйти»"] --> login
```

После перезагрузки страницы сессия восстанавливается через `POST /auth/refresh` (cookie, `access_token` хранится
только в памяти). Закрытый маршрут без сессии ведет на `/login` и после входа возвращает на исходный адрес.

### 1.2 Создание и начало встречи (UC-2, начало UC-4)

```mermaid
flowchart TD
    meetings["Главная /meetings<br/>«Ближайшие», «Прошедшие», поиск"] --> choose{"Что нужно?"}
    choose -- "«Начать сейчас»" --> instant["Встреча создается и<br/>организатор входит сразу"]
    choose -- "«Запланировать»" --> form["/meetings/new<br/>название, время, анализ, кадры/с"]
    form --> created["«Встреча создана»:<br/>ссылка-приглашение"]
    created --> copy["«Копировать ссылку» →<br/>отправляет участникам"]
    created --> card["«Открыть карточку»<br/>/meetings/:id"]
    meetings --> card
    card --> edit["Правка: название – всегда,<br/>остальное – пока встреча не началась"]
    card --> delete["«Удалить» (с подтверждением)"]
    card --> start["«Начать встречу»"]
    instant --> room
    start --> room["Комната /room/:id"]
```

Создание и отправка ссылки укладываются в три действия: ввести название → «Создать и получить ссылку» →
«Копировать ссылку».

### 1.3 Комната организатора (UC-4) и завершение (UC-5)

```mermaid
flowchart TD
    room["Комната: галерея, шапка, панель управления"] --> consent{"Анализ включен<br/>во встрече?"}
    consent -- "да" --> own["«Анализ моих эмоций» –<br/>по умолчанию выключен,<br/>включается явно"]
    consent -- "нет" --> plain["Без анализа и без панели эмоций"]
    room --> side["Боковая панель:<br/>«Участники», «Эмоции», «Чат»"]
    side --> moder["Модерация (с подтверждением):<br/>выключить микрофон, выключить камеру,<br/>удалить из встречи"]
    room --> leave["«Выйти» – организатор<br/>выходит, встреча продолжается"]
    room --> finish["«Завершить встречу»<br/>(подтверждение «для всех»)"]
    finish --> card2["Карточка встречи /meetings/:id"]
    card2 --> report["Отчет: сводка, динамика,<br/>ключевые моменты, участники"]
    report --> export["Экспорт PDF / CSV (UC-6)"]
```

Панель эмоций, сводка и отчет сейчас на тестовых данных, в интерфейсе есть пометка «Демонстрационные данные».
Экспорт – заглушка, появится в спринте 5.

## 2. Участник (гость, без аккаунта)

### 2.1 Присоединение по ссылке (UC-3)

```mermaid
flowchart TD
    link(["Ссылка /j/код"]) --> info{"GET /join/код"}
    info -. "не найдена" .-> nf["«Приглашение не найдено»"]
    info -. "завершена или отменена" .-> ended["«Встреча завершена» /<br/>«Встреча отменена»"]
    info -- "ок" --> lobby["Лобби:<br/>превью, выбор камеры, микрофона, динамика,<br/>уровень микрофона"]
    lobby --> dev{"Доступ к устройствам?"}
    dev -. "запрещен или устройства нет" .-> devmsg["Сообщение по-русски + «Повторить»;<br/>войти можно без устройства"]
    dev -- "да" --> form
    devmsg --> form["Имя + явный выбор согласия<br/>(по умолчанию не выбрано)"]
    form --> submit{"«Войти во встречу»<br/>POST /join/код"}
    submit -. "имя не указано или нет выбора" .-> form
    submit -- "встреча не началась" --> wait["«Встреча еще не началась»:<br/>повтор каждые 5 с до 10 минут,<br/>«Отменить ожидание»"]
    wait --> submit
    wait -. "10 минут прошло" .-> form
    submit -. "комната заполнена (10)" .-> full["Сообщение, вход снова доступен"]
    submit -. "уведомление обновилось" .-> form
    submit -- "ок: participant_token" --> room["Комната /room/:id"]
```

### 2.2 Комната участника и выход

```mermaid
flowchart TD
    room["Комната участника"] --> a["Галерея, чат, «Участники»<br/>(свой статус согласия)"]
    room --> c["«Анализ моих эмоций» →<br/>PUT /participants/me/consent"]
    c --> c2["Отзыв: анализ прекращается,<br/>накопленное остается у организатора"]
    room --> leave["«Выйти»"] --> left["«Вы вышли из встречи»<br/>+ «Вернуться во встречу»"]
    room --> lost["Обрыв соединения"] --> re["«Связь пропала.<br/>Переподключаемся…»"]
    re -. "не удалось" .-> lost2["«Соединение потеряно» +<br/>«Подключиться снова»"]
    room --> rm["Организатор удалил"] -.-> removed["«Вас удалили из встречи»<br/>повторный вход по токену закрыт"]
    room --> fin["Организатор завершил"] -.-> done["«Встреча завершена»"]
```

Участник не видит чужие эмоции и отчет. После перезагрузки вкладки комната запрашивает новый токен LiveKit по
`participant_token` (`POST /participants/me/rejoin`).

## 3. Администратор (UC-7)

```mermaid
flowchart TD
    start(["Вход как admin"]) --> menu["Меню организатора +<br/>пункт «Администрирование»"]
    menu --> admin["/admin"]
    admin --> users["Пользователи: список,<br/>«Заблокировать» / «Разблокировать»"]
    admin --> live["Идущие встречи и число участников"]
    admin --> health["Состояние сервисов:<br/>auth, meeting, realtime, analytics,<br/>ML, LiveKit, Kafka, БД"]
    users --> block["Блокировка отзывает сессии;<br/>заблокированный не входит: «Аккаунт заблокирован»"]
```

Раздел `/admin` – заглушка (спринт 6, EMO-106). Отчеты организаторов администратору недоступны. Может ли
администратор проводить собственные встречи, не решено (вопрос к архитектору, см. [site-structure.md](site-structure.md)).

## 4. Сводка по прецедентам

| Прецедент | Роль | Экраны | Реализация клиента |
|---|---|---|---|
| UC-1 Регистрация, вход | Организатор, админ | `/register`, `/login`, `/settings` | Реализовано, проверено с настоящим auth-service |
| UC-2 Создание встречи | Организатор | `/meetings`, `/meetings/new`, `/meetings/:id` | Реализовано (mock и `dev-api`) |
| UC-3 Присоединение по ссылке | Участник | `/j/:code` | Реализовано (mock и `dev-api`) |
| UC-4 Встреча и панель эмоций | Организатор, участник | `/room/:id` | Видеосвязь, чат, модерация, согласие – на LiveKit; панель эмоций – мок |
| UC-5 Просмотр отчета | Организатор | `/meetings/:id` | Мок |
| UC-6 Экспорт | Организатор | `/meetings/:id` | Заглушка |
| UC-7 Администрирование | Администратор | `/admin` | Заглушка |
